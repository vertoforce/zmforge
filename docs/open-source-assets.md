# Open-source assets: free models, found art and drawn textures

zmforge dresses its maps with free assets only: CC0 3D models, public-domain
or CC0 photos, and textures its own code draws. This page covers where those
come from, how to check a licence before using one, and how a free model
becomes a Black Ops III xmodel.

- **Models:** Kenney kits and Poly Haven photoscans, all CC0. Downloaded at
  build time, never committed. Some props are generated by our own code and
  textured with an ambientCG CC0 photo (the hay bales).
- **Textures and loading screens:** drawn by `src/zmforge/texture/` from
  nothing, from the map plan, or from a room scan you supply.
- **Engine limits:** builds of up to 39,975 props have linked. Model triangles do not
  count toward the map's triangle cap. Only the first 340 shadowing omni
  lamps keep their shadows.

The bytes of every downloaded asset stay out of git. The repository keeps
the record of what was downloaded, from where, under which licence.

## Finding free models

Use CC0 or public domain where you can. A map is a compiled fastfile that
anyone who downloads it can open, so a licence that forbids extraction or
requires ShareAlike is a problem even when the model was free.

<details><summary>What this project used, and what it searched</summary>

- **Used:** Kenney kits (<https://kenney.nl/assets>), all CC0 1.0: Food Kit,
  Furniture Kit, Graveyard Kit (pumpkins, gravestones, fences, hay), Nature
  Kit (corn), Car Kit (tractor), Fantasy Town Kit (hand cart).
  `src/zmforge/props/library.py` lists every prop with its kit and source file.
- **Searched for a scarecrow and a wheelbarrow, none found as CC0:** Kenney,
  Poly Pizza with its CC0 filter, OpenGameArt, KayKit's free Halloween Bits.
  Every Poly Pizza wheelbarrow or scarecrow was CC-BY, and KayKit's scarecrow is in its paid tier.
  The map uses a hand cart and a pumpkin on a wooden cross instead.
- **Used:** Poly Haven (<https://polyhaven.com/license>,
  CC0) `dead_tree_trunk`, `tree_stump_01` and `wooden_crate_02`, imported
  from glTF and decimated; ambientCG (<https://docs.ambientcg.com/license/>,
  CC0) `ThatchedRoof001A` straw on the generated hay bales and `Leaf001`
  (cropped, graded olive to straw) on the generated corn stalks. How:
  steps 1-6 below.
- **Searched for realistic hay, pumpkin and corn, none found as CC0:**
  Poly Haven, ambientCG, Sketchfab's CC0 filter.
- **Also CC0, not used here:** Quaternius model packs.
- **Left out on purpose:** paid marketplaces. Their licences require the model
  to stay non-extractable, and a shipped fastfile is extractable.

</details>

<details><summary>Checking a licence before you use a model or picture</summary>

- Read the licence on the source page, not the search result's label. Tags
  are typed by whoever uploaded the file.
- CC0 and public domain: no conditions. Use them.
- CC-BY: allowed, but every map that ships it must credit the author. Keep a
  credits file with the map.
- CC-BY-SA: the map inherits ShareAlike. This project drops these.
- NC (non-commercial) or "editorial only": leave out. The terms of what a
  published map may be are not yours to set.
- Record the page URL, file URL, creator, licence and the licence sentence
  itself when you download. For props, `src/zmforge/props/library.py` is that
  record.

</details>

## From OBJ to xmodel

`zmforge props <map>` turns library entries into files the mod tools convert.
The code is in `src/zmforge/props/`.

<details><summary>The steps</summary>

1. `fetch.py` downloads the kit archive into `assets-cache/`, once. It never
   re-fetches, so a built map's kit cannot change under it.
2. `wavefront.py` reads the `.obj`: positions, normals, UVs, triangles and
   material names. zmforge reads OBJ only. Convert glTF or FBX to OBJ first.
3. `xmodel.py` writes `.XMODEL_EXPORT` text, version 7, one `TAG_ORIGIN` bone.
   It maps Y-up to Z-up, scales the model so its longest axis matches the size
   the prop should be in inches, and drops its lowest point to the floor.
4. `collision.py` writes a box bullet-collision model (`<name>_col`) and a
   brush collmap, the two collision paths stock models use.
5. `gdt.py` and `build.py` write the xmodel, image and material entries, one
   `.tif` per kit texture, `props.json` with every measured number, and
   `PROP-CREDITS.md` with each prop's source and licence.
6. Copy the tree into the mod tools
   root, run `gdtdb\gdtdb.exe /update`, then link. The linker converts the
   xmodels and images.

</details>

<details><summary>The inside-out fix: EXPORT_CORNER_ORDER</summary>

- The first kit props (pumpkin, tractor, donut, teddy bear) rendered inside
  out in game.
- Measured on converted meshes: stock models' face winding disagrees with
  their vertex normals on 0 to 1 triangles each. The kit props, written in
  `.obj` order, agreed on all of them, so the order was backwards.
- The Y-up to Z-up swap keeps winding (its determinant is +1). The engine's
  winding is the reverse of Wavefront's.
- `xmodel.EXPORT_CORNER_ORDER = (0, 2, 1)` writes each triangle's corners
  in that order, which fixed it. UV v is also flipped, because this format's
  v runs down.

</details>

<details><summary>Stock models and the installed-assets ledger</summary>

- A stock asset name can be in a shipped map and still not compile on a
  standard install. GDT files do not list every name the compiler resolves.
- The ledger `src/zmforge/blueprint/installed_assets.json` records, for each
  candidate model, whether a throwaway map that places it compiled. That file
  holds names only.
- `scripts/scan-local-tools.py` rescans your own mod tools folder for models a
  GDT declares but whose LOD or collision files are missing, so they compile
  and then fail to link.
- Check Z13 fails a map that names a model the ledger says will not compile.

</details>

<details><summary>Engine limits for dressing, measured</summary>

Measured with a probe map compiled, lit and linked by the mod tools:

- 6,000 props (2.9M model triangles) and 9,017 props (about 4.5M) both
  linked with no limit or overflow line.
- Larger builds of zm_corn_maze linked too: 21,232 props, and padded builds
  of 15,000, 25,000 and 39,975 props, all compiled, baked and linked with no
  limit line. 39,975 is the largest prop count proven to link.
- Model triangles do not count toward `MAX_MAP_TRIANGLES`. That cap covers
  brushes and terrain only.
- The light bake keeps shadows for the first 340 shadowing omni lights and
  drops the rest with an error line. The link still succeeds.
- Load time and frame rate in game at those counts are not measured.

</details>

## Found art and drawn textures

<details><summary>Textures drawn by code</summary>

- Loading screens are drawn from the map's own plan (`emit/planview.py`) or
  by a per-map painter in `texture/*_loadscreen.py`.
- Fonts: Anton and Oswald (SIL OFL 1.1), downloaded and recorded in
  `assets-cache/fonts/FONTS.json`, plus OS packages (Liberation, URW base35,
  DejaVu) read in place. No font file is committed.
- `zmforge textures` cuts tiling materials from a photogrammetry scan you
  supply. No scan is included.

</details>
